## 1. 产品概述

### 1.1 一句话
一家呈现在网页上的日式寿司小店。访客用鼠标在店里探索，看菜单、和师傅聊天、自选鱼生、点菜，
并把吃过的鱼生和刺身收集成图鉴。

### 1.1.1 命名
- **店名**：小舟（こぶね · Kobune Sushi）。寿司店常用船形器皿（舟盛り）盛刺身，名字小巧、有画面感。暖帘写「小 舟 鮨」，招牌标志为「舟」。
- **师傅**：春田师傅（春田さん），默认男性。
- **厨师画风**（Jacey 2026-10-30 最新确认）：采用示意图 **C 的微缩手作人偶风**。圆脸、小巧深色眼睛、腮红、立体发束、柔软棉麻质感；不用动漫式五官、平面几何拼接或粗描边。男性春田穿奶油白交领板前服、靛蓝前挂、米白鉢巻。场景和对话头像共用 `assets/art/haruta.webp`。
- **统一画风**（最新决定替代早期平涂 / 复古混合方案）：温馨、可爱、有生活细节的微缩居酒屋。蜂蜜木色和奶油白为主，陶土红、靛蓝和少量鼠尾草绿点缀。木纹、布料、陶器有可见材质，灯笼局部暖光，界面使用奶油纸面、圆角及柔和阴影。
  - 场景采用原创生成的本地 WebP 底图，叠加独立男性角色、可访问 SVG 热点及轻微动态；不依赖外部渲染库、运行时生成或网络图片。
  - 食物仍按 `data.js` 动态生成 SVG，通过细描边、渐变、高光、颗粒和投影表现柔和体积，不用一张通用插画替代不同鱼种。
  - 客人保留原有自定义服装、颜色、发型与配饰，增加衣料明暗及柔和投影；当前仍是程序绘制背影。
  - 动画仅用于师傅轻微呼吸、灯笼光晕与蒸汽；所有动画尊重减少动态效果设置。
- **本次角色范围**（Jacey 后续明确）：只制作默认男性春田；“当 chef / 当顾客”尚未实现，继续留在 T-10。女性示意图只作后续设计参考，性别选择 UI 和女性运行时素材暂缓。
- **客人**：访客自己，形象可自定义（F-13）。

### 1.2 目标
1. **氛围**：一打开就像走进一家安静的日式小店（和纸、木头、暖帘、灯笼、竖排字）。
2. **探索**：店里的每样东西都可以悬停、点击，有反馈、有内容。
3. **点菜**：多种菜单形式都能点；可以自选鱼生，也可以交给师傅。
4. **收集**：吃过的鱼进入图鉴，有稀有度和隐藏鱼，让人想再来。

### 1.3 非目标（当前阶段不做）
- 真实下单、支付、外卖、账号系统、后端服务器
- 多人在线
- 复刻任何现有游戏或真实店铺的品牌与形象（店名、师傅、美术都是原创）

### 1.4 目标用户
- 对日料感兴趣、想轻松逛一逛的访客（桌面浏览器为主，手机可用）
- 喜欢收集要素的休闲玩家

## 2. 体验原则

| 原则 | 说明 |
| --- | --- |
| 日式风 | 配色采用奶油白、蜂蜜木色、陶土红、靛蓝及鼠尾草绿（见 `css/style.css` 的 `:root`）。标题用毛笔字体，菜单尽量竖排。 |
| 每个热点都有回应 | 悬停：高亮 + 提示气泡；点击：打开对应弹窗。不能有“点了没反应”的东西。 |
| 中英双语，日语点缀 | 界面有简体中文和英文两个版本，访客在顶栏随时切换（F-14）。菜名、标题保留日语。图鉴同时给出中文、日语、英语。 |
| 不打断 | 不用浏览器 `alert/confirm`；提示用页面底部的 toast。 |
| 零门槛 | 纯静态页面，双击 `index.html` 即可运行，不需要安装和构建。 |
| 可访问 | 热点可用键盘 Tab 聚焦、Enter 打开；Esc 关闭弹窗；尊重“减少动态效果”设置。 |

## 4. 功能规格

每条功能都写了**验收标准（AC）**。改动某个功能时，改完要保证它的 AC 仍然成立。

### F-01 店内场景
- 场景是 `index.html` 里的一张内联 SVG（`viewBox="0 0 1200 800"`），使用本地微缩场景底图与独立角色。桌面随窗口等比缩放；≤600px 场景保留 840px 宽，可横向滑动，页面本身不横向溢出。
- 可互动物体是 `<g class="hotspot" data-id="...">`。同一个 `data-id` 可以出现多次（例如吧台凳和榻榻米都是 `seats`），悬停任意一个会一起高亮。
- 装饰物不是热点；灯笼光晕、蒸汽与角色呼吸为 CSS 动画。场景下方另有菜单、鱼柜、师傅、抽签快捷入口，手机和键盘也能直接访问。
- **AC**：每个热点悬停时有发光高亮和提示气泡（标题 + 说明，来自 `SHOP_DATA.hotspots`）；点击打开对应视图；Tab 可聚焦，Enter/空格可打开。

### F-02 暖帘 · 店铺介绍
- 介绍店名、各热点用途，提供“去选座位”“直接看菜单”按钮。
- **AC**：新访客读完就知道怎么玩。

### F-03 门口立牌 · 本日のおすすめ
- 黑板风格，竖排粉笔字；列出今日鲜货（从非隐藏鱼中按日期种子取 4 种）和“おまかせ”。
- 点击鱼 = 加一份该鱼刺身到订单；点击おまかせ = 打开师傅。
- **AC**：同一天刷新内容不变；换一天内容变化。

### F-04 / F-05 / F-06 菜单
- 三种不同呈现：木札（竖排木牌）、酒单（瓶子卡片）、菜单册（分页签列表）。
- 刺身分类由 `fish` 数据**自动生成**（排除 `omakaseOnly` 的鱼）。
- 菜单册里已收录进图鉴的鱼显示“已收录”。
- **AC**：任何菜单项点击后都能加入订单，并有 toast 和顶栏数字变化。

### F-07 师傅
- 问候语随机；坐吧台时 60% 概率说吧台专属台词。
- おまかせ：按权重抽 3 种不重复的鱼，价格为原价合计 × 0.9（取整到 10）。权重：並 40、上 26、特上 10 + 运气×3、幻 2 + 运气×5。
- 可以“换一换”重抽，或“就要这盘”加入订单。
- **AC**：`omakaseOnly` 的鱼只能从这里获得；抽签运气越好，越容易出高稀有度。

**师傅形象**：`app.js` 的 `chefSVG()` 返回本地透明 WebP 的 SVG `<image>`；默认且当前唯一运行时角色是男性春田。场景按吧台高度裁切身体，对话头像从同一角色资源取景。旧 `?chef=female` 调试入口已移除；女性形象和玩家角色选择均留待 T-10，不包含在本次重制。CSS 提供轻微呼吸，减少动态效果时静止。

### F-08 鱼柜 · 自选鱼生
- 左侧鱼柜列出所有非隐藏鱼；点一次往盘子里放一份（三切）。最多 6 份。
- 盘子是圆盘，份数均匀环绕排列，中间有萝卜丝、紫苏、山葵；点盘中的鱼可拿掉。
- “放入订单”生成一条“自选刺身拼盘”，备注写明组成。
- **AC**：盘子实时反映选择；价格 = 各份价格之和。

### F-09 座位
- 两种：吧台席 `counter`、和室座敷 `tatami`（数据在 `SHOP_DATA.seats`）。
- 选座后保存到本地，顶栏显示，客人形象（F-13）坐到该座位的 `marker` 坐标上。
- **AC**：未选座时下单，会先跳到选座，选完自动回到订单。

### F-10 订单与下单
- 订单行：名称、备注、数量加减（减到 0 删除）、小计；合计。
- **用餐方式**：订单页顶部可以选「店内堂食」或「打包带走」，默认堂食。堂食必须先选座位；打包不需要座位。
- 下单：把所有行涉及的鱼加入图鉴（打包也算吃过）；清空订单；显示小票（新收录的鱼以卡片展示）和金色 toast。
- 小票插画：堂食时把这次点到的鱼做成握寿司，摆在木屐盘上（最多 5 贯）；打包时装进**外带盒**，即黑色托盘、绿色叶片隔断、透明塑料盖，再贴一张「小舟」红色标签（8 格，按点到的鱼依次排列）。印章分别是「注文承り」和「お持ち帰り」。
- **AC**：重复吃同一种鱼不会重复收录；刷新页面后图鉴进度还在，订单清空；打包下单不会弹出选座。

### F-11 鱼图鉴
- 网格卡片：编号、稀有度、鱼片图、名字。未收录显示剪影和“？？？”，隐藏鱼提示“只在师傅推荐中出现”。
- 进度条、稀有度筛选；新收录的卡片闪光一次。
- 详情页：中文名、日语名（假名 / 汉字 / 罗马音）、英语名、稀有度、**口感**、风味、旬、价格、介绍。
- **AC**：集齐时显示完成文案；每种鱼的详情字段齐全。

### F-13 客人形象 · お客さん
- 客人以**背影**出现在所选座位上（面向师傅），没选座时不显示。
- 可选项来自 `SHOP_DATA.guest`：发型（短发 / 丸子头 / 马尾 / 长发）、发色、服装款式（便服 / 和服 / 浴衣）、衣服颜色、配饰（无 / 发簪 / 帽子），每组第一项为默认值；支持“随机一下”。
- 和服：宽袖、白色后领、金色宽腰带，背后打着结；浴衣：袖子窄一些，有白色小圆花纹，系红色腰带。颜色跟着「颜色」选项变。
- 入口：点击场景里的自己，或选座弹窗里的「换个样子」。选择保存在本地。
- 画法在 `app.js` 的 `guestSVG(guest)`，原点是座位面中心、向上绘制；场景和预览共用。
- **AC**：改任意选项，预览和场景里的形象同时更新；刷新后保持；换座位时形象跟着移动。

### F-14 中英双语 · Language
- 两种语言：简体中文 `zh`、英文 `en`。顶栏按钮显示“要切换到的语言”（中文界面显示 `EN`，英文界面显示 `中文`）。
- 首次访问按浏览器语言决定（`zh*` → 中文，其他 → 英文）；之后记住选择（`kobune.lang`）。
- 切换后立即生效：顶栏、提示、热点提示和无障碍标签、当前打开的弹窗都会重绘；已经在订单里的菜名也跟着变。
- 日语元素（暖帘、立牌竖排字、弹窗日文标题、假名）在两种语言下都保留，它们是氛围的一部分。
- 图鉴详情：中文界面主标题是中文名、副标题有英文名；英文界面反过来。
- 顶栏在弹窗打开时仍可点击（弹窗会让出顶栏的高度）。
- **AC**：任意界面切换语言，看不到残留的另一种语言文案（日语除外）；刷新后保持所选语言；缺翻译时显示中文，不报错。

### F-12 招财猫 · おみくじ
- 随机抽一支签（大吉～末吉），本次访问内运气取最高值，影响 F-07 权重。
- **AC**：运气不保存，刷新后归零。

## 5. 数据模型

所有内容数据在 `js/data.js` 的 `window.SHOP_DATA`。**加内容只改数据，不改逻辑。**

### 5.1 Fish（鱼）
| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| `id` | string | ✓ | 唯一，英文小写，**发布后不要改**（图鉴存档用它） |
| `name` | string | ✓ | 中文名 |
| `jp` / `kanji` / `romaji` | string | ✓ | 日语假名 / 汉字 / 罗马音 |
| `en` | string | ✓ | 英文名 |
| `rarity` | 1–4 | ✓ | 1 並 · 2 上 · 3 特上 · 4 幻 |
| `price` | number | ✓ | 一份（三切）价格，日元 |
| `color` / `color2` | hex | ✓ | 鱼片主色 / 纹理色 |
| `shape` | enum | ✓ | `slice` `round` `shrimp` `roe` `pearl`（CSS 在 `.slice.*`） |
| `season` / `texture` / `flavor` / `desc` | string | ✓ | 旬 / 口感 / 风味 / 介绍 |
| `omakaseOnly` | boolean | | true = 不进菜单和鱼柜，只能おまかせ获得 |

> 注意：图鉴编号 = 在 `fish` 数组里的位置。**新鱼只往数组末尾加**，不要插队或删除，否则老玩家的编号会变。

### 5.2 Menu（菜单）
`menu` 是分类数组：`{ id, name, jp, items[] }`。`auto: true` 的分类（刺身）由鱼数据生成。
MenuItem：`{ id, name, jp, price, desc?, fish?: string[], bottle?: hex }`。
- `id` 全局唯一。有 `fish` 的菜下单后会收录这些鱼。`bottle` 仅饮品用。

### 5.3 其他
- `rarity`：`{ label, zh, color }`
- `seats`：`{ id, name, jp, desc, marker: [x, y] }`（marker 是客人坐下的 SVG 坐标）
- `guest`：`{ hairStyle[], hairColor[], clothing[], outfit[], accessory[] }`，每项 `{ id, name, color? }`。新增发型或配饰需要同时在 `guestSVG` 里加画法；只加颜色只改数据。
- `hotspots`：`{ [data-id]: { title, hint } }`
- `chef`：`greetings[]`、`counterExtra[]`、`omakaseIntro`、`legendary`、`afterOrder[]`
- `omikuji`：`{ result, text, luck: 0–3 }[]`
- `chefLooks`：`{ id, name }[]`，为 T-10 预留的男女配置；当前运行时仅男性春田。英文在 `data.en.js` 的 `chefLooks`。

### 5.3.1 翻译数据
- **界面文案**：`js/i18n.js` 的 `window.I18N = { zh: {...}, en: {...} }`，扁平 key（如 `"cart.submit"`），支持 `{name}` 占位符。两种语言的 key 必须一一对应。
- **内容英文**：`js/data.en.js` 的 `window.SHOP_DATA_EN`，按 `id` 对应 `data.js`：`fish[id]`（season / texture / flavor / desc）、`menu[id]`（name / desc）、`categories`、`seats`、`guest`（按选项 id）、`hotspots`、`rarity`、`chef`（数组与中文**按位置对应**）、`omikuji`（按位置对应）。
- 鱼的英文名用 `data.js` 里已有的 `en` 字段，不重复写。
- 缺英文时回退中文。**新增任何中文内容或文案，必须同时补英文**（见 §7.2）。

### 5.4 运行时状态与本地存档
`app.js` 里的 `state`：`lang`、`cart`、`plate`、`seat`、`collected`、`fresh`、`guest`、`luck`、`omakase`、`menuTab`、`zukanFilter`。

本地存档（localStorage，前缀 `kobune.`，读写失败时静默。店名改名前用的是 `koharu.`，读取时会回退兼容旧存档）：
| key | 内容 |
| --- | --- |
| `kobune.seat` | 座位 id |
| `kobune.zukan` | 已收录鱼 id 数组 |
| `kobune.fresh` | 尚未在图鉴里看过的新收录鱼 id |
| `kobune.guest` | 客人形象 `{ hairStyle, hairColor, clothing, outfit, accessory }` |
| `kobune.lang` | 界面语言 `zh` / `en` |

> 新增存档 key 必须写进这张表；**改变已有 key 的格式需要写迁移代码**。

### 5.5 存档的局限与方案
网站不需要登录，进度存在**访客自己的浏览器里**（localStorage）。

| 情况 | 进度还在吗 |
| --- | --- |
| 普通刷新、关掉标签页再打开、重启电脑 | ✅ 在 |
| 同一台电脑换一个浏览器（例如 Chrome → Safari） | ❌ 看不到 |
| 换设备（电脑 → 手机） | ❌ 看不到 |
| 清除浏览器数据 / 缓存与网站数据 | ❌ 丢失 |
| 无痕 / 隐私模式 | ❌ 关掉窗口就丢失 |
| 浏览器禁用了本地存储 | ❌ 无法保存（页面照常能玩） |

方案（按优先级）：
1. **导出 / 导入存档码（T-07，v0.2）**：在图鉴里提供“导出存档”，把全部 `kobune.*` 存档打包成一段文字码（JSON → Base64，带版本号和校验）；可以复制、下载成文件或生成二维码。在另一台设备“导入存档”粘贴即可恢复。仍然不需要登录、不需要服务器。
2. **提醒**：图鉴收集到一定数量（例如 5 种）时，用 toast 提醒一次“记得导出存档”。
3. **云同步（T-31，可选，后期）**：如果以后需要跨设备自动同步，需要引入账号和后端（例如 Supabase / Firebase，或用“同步码”匿名绑定）。这会打破“纯静态、无服务器”的约束，需要 Jacey 决定（§10 Q7）。

## 6. 技术架构

### 6.1 约束
- 纯 HTML / CSS / 原生 JS，不引入框架和构建工具；外部网络资源只用 Google Fonts（不可用时使用系统字体）。场景与角色资源随仓库本地提供，`file://` 可用。
- 要能直接用 `file://` 打开（所以不用 ES module 的 `import`，用普通 `<script>` 按顺序加载）。
- 脚本加载顺序：`i18n.js` → `data.js` → `data.en.js` → `art.js` → `app.js`。

### 6.2 文件
```
index.html        页面骨架 + 本地底图、独立角色、SVG 热点与动态图层
css/style.css     全部样式（按区块分节：顶栏 / 场景 / 弹窗 / 各视图 / 响应式）
js/i18n.js        界面文案（中 / 英）I18N
js/data.js        内容数据 SHOP_DATA（中文为源）
js/data.en.js     内容数据的英文翻译 SHOP_DATA_EN
assets/art/       原创生成场景与男性角色（本地 WebP），来源登记见 §11
js/art.js         食物插画 KOBUNE_ART（刺身、握寿司、军舰、细卷、木屐盘、外带盒），统一画风参数 T
js/app.js         交互逻辑
docs/PRD.md       本文档
CLAUDE.md         给 agent 的入口说明（指向本文；AGENTS.md 内容相同，供其他 agent 工具读取）
```

### 6.3 视图约定（最重要的扩展点）
所有弹窗内容都是一个“视图”，注册在 `app.js` 的 `views` 对象上：
```js
views.<id> = {
  cls: "book",               // 可选，弹窗外观 class，默认用 id
  render: (...args) => html, // 返回弹窗内部 HTML 字符串
  mount: (...args) => {},    // 可选，HTML 插入后绑定事件
};
```
- 打开：`open(id, ...args)`；按当前视图重绘：`rerender(...args)`；关闭：`close()`。
- 弹窗内的通用按钮无需绑定：`data-add="<menuItemId>"` 加入订单，`data-open="<viewId>"` 切换视图。
- 场景热点的 `data-id` 与视图 id 同名，点击自动打开。

**新增一个可互动物体的步骤**：① `index.html` 场景里画 `<g class="hotspot" data-id="xxx">` ② `data.js` 的 `hotspots.xxx` 写提示，`data.en.js` 的 `hotspots.xxx` 写英文 ③ `app.js` 加 `views.xxx`，所有文案用 `t("key")`，key 同时加进 `i18n.js` 的 zh 和 en ④ 需要的样式加到 `style.css` 对应分节。

### 6.3.1 插画约定（art.js）
- `KOBUNE_ART.sashimi(f, n)`、`nigiri(f)`（`shape` 是 roe / pearl 的鱼会自动画成军舰）、`maki(f)`、`geta(fishList)`、`takeoutBox(fishList)`，每个都返回一段 `<svg class="art …">` 字符串。
- 细描边、米饭颜色、配色偏暖程度和颗粒感从 `T` 读取。每张 SVG 分配独立渐变 id，避免多个鱼卡片串色；轻微投影由 CSS 提供。
- 纸张颗粒来自 `index.html` 里的 `#kb-grain` 滤镜，只加在食物插画上。

### 6.4 公共函数（app.js 内）
`addToCart(line)`、`addMenuItem(id)`、`toast(msg, gold)`、`updateHud()`、`swatchHTML(fish, n)`（刺身）、`sushiHTML(fish)`（握寿司）、`plateInnerHTML(fishIds, removable)`、`cardHTML(fish, isNew)`、`guestSVG(guest)`、`chefSVG()`、`itemArt(menuItem)`、`store.get/set`。
语言相关：`t(key, vars)` 取界面文案；`fishName(f)`、`fishText(f, field)`、`itemName(it)`、`itemDesc(it)`、`seatName(s)`、`rarityName(r)`、`chefLine(key, i?)` 取当前语言的内容；`applyLang()` 刷新整页。
CartLine 结构：`{ key, kind: "item" | "plate" | "omakase", price, qty, fish: string[], counts? }`。名称和备注不存死，显示时由 `lineName(l)` / `lineNote(l)` 按当前语言生成。

## 7. 多 agent 协作规范

### 7.1 工作流
1. 从 [§9](#9-任务清单) 认领一个状态为 `待做` 且依赖已完成的任务，把状态改成 `进行中 (@你的名字/分支名)`，**这个改动单独先提交**，避免两人撞车。
2. 分支命名：`feat/T-xx-简述`、`fix/...`、`docs/...`。一个任务一个分支、一个 PR。
3. PR 标题带任务编号，描述写明：改了什么、对应哪些 AC、怎么测的、截图。
4. 合并后把任务状态改为 `完成`，并更新 §3 / §4 中受影响的内容。
5. 产品决策（玩法、文案风格、要不要做某功能）不要自己定：写进 §10，等 Jacey 回复。

### 7.2 文件冲突规则
| 文件 | 规则 |
| --- | --- |
| `js/data.js` | 只在自己负责的数组/对象**末尾追加**；不重排、不删已有条目；不改已有 `id`。 |
| `js/data.en.js` / `js/i18n.js` | 加中文内容或文案的同一个 PR 里必须补英文；只追加自己的 key。英文由 agent 起草即可，Jacey 可后续润色。 |
| `js/app.js` | 每个视图是独立代码块，只改自己任务涉及的 `views.<id>` 和必要的公共函数。改公共函数要在 PR 里点名。在 T-01 完成后，视图拆到 `js/views/*.js`，冲突会少很多。 |
| `index.html` | 场景 SVG 按物体分组并有中文注释；新物体加在“你在这里”标记之前。 |
| `css/style.css` | 在对应分节内追加；新视图新建分节注释 `/* 视图名 */`。不改 `:root` 颜色变量，除非任务就是改配色。 |
| `docs/PRD.md` | 只改自己任务那一行和相关功能小节。 |

### 7.3 代码风格
- 2 空格缩进、双引号、`const` 优先；跟周围代码保持一致的注释密度（中文注释）。
- 界面文案不要写死在 `app.js` 里，一律走 `t()`；不要出现 `alert`/`confirm`/`prompt`。
- 动画都要被 `prefers-reduced-motion` 覆盖（全局规则已处理，别用 JS 强制动画）。
- 不引入新依赖；如确有需要，先写进 §10。
